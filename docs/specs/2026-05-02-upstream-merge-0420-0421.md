## 4. Integration Strategy

### 4.1 Approach: Sequential Cherry-Pick with Manual Resolution

**Why not rebase:** Our branch has 186 commits with merge commits; interactive rebase would be destructive and error-prone.

**Why not merge:** A direct merge of upstream/main would bring in `82ccf66` which we're explicitly excluding.

**Procedure:**

1. Create a new integration branch from current `update` HEAD (`e3c81ac`):
   ```bash
   git checkout -b merge-upstream-0420-0421 update
   ```

2. Cherry-pick in dependency order:
   ```bash
   # SDK bump first (enables effort option used by later commits)
   git cherry-pick b6a16b6

   # Permission mode feature (largest, most conflicting)
   git cherry-pick 1bd8667

   # Diff viewer fixes (independent, clean)
   git cherry-pick d46b3af
   git cherry-pick e0cea68

   # SSH color warning (clean, additive)
   git cherry-pick 15f4e81

   # Special-char crash fix (conflicts with our _sanitize_id)
   git cherry-pick 796dbd4
   ```

3. Resolve conflicts per Section 3.1 resolution strategies.

4. Run verification:
   ```bash
   uv run python -m pytest tests/ -n auto -q
   uv run pre-commit run --all-files
   ```

### 4.2 Conflict Resolution Principles

1. **Our security fixes are non-negotiable:** `notify()` override with `markup=False` default and `strip_ansi()` stay. Upstream removed these — we re-add them.
2. **Our context tracking is non-negotiable:** `_prepare_prompt()`, `update_context()`, `TOKEN_REMINDER_PATTERN` stay. Upstream's version doesn't have these.
3. **Upstream's permission mode is additive:** It adds a new mode without removing our features. Accept fully.
4. **Upstream's diff fixes take precedence:** Their `_sanitize_id` regex approach is strictly better than our character-replacement. Their tab/syntax fixes are on files we haven't touched.
5. **SDK version:** Keep our higher floor (`>=0.1.55`) since it's a superset.

### 4.3 Post-Merge Reconciliation

After cherry-picks land cleanly:

| Task | Reason |
|------|--------|
| Add "auto" to our `PermissionMode` cycle in footer | Upstream adds auto; our footer is richer — needs manual wiring |
| Wire `get_default_permission_mode()` to our `AgentManager.create_agent()` | Upstream adds it; our agent creation path is different |
| Verify `_sanitize_id` tests | We have existing tests; upstream's regex version must pass them |
| Verify `refresh_context()` still works with SDK >=0.1.36 | SDK bump may change `get_context_usage()` behavior |
| Update `pyproject.toml` version to development target | Set to `0.4.20.0-dev` or similar |
